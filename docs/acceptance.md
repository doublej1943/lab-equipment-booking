## C 的复测顺序

1. 检出 PR #6 的最新提交，记录提交号、机器、版本和运行时间。[环境配置和运行命令](development-runtime.md)
2. 用两个普通账号、一个管理员走六条路径。E2E-01 登录、看时段、提交并在本人记录找到预约；E2E-02 取消并重订；E2E-03 重复提交与跨设备预约；E2E-04 停用、检查影响、核实对应联系方式；E2E-05 提交确认丢失后从本人列表或详情核实；E2E-06 为每个适用的权限拒绝配对一次合法访问。确认原始 POST 的状态，再跟随跳转。
3. 执行完整测试，保留终端摘要和证据目录。失败时记录发生在哪个 Story/AC、提交号、步骤、预期、实际、原始状态码以及独立查库结果。隐私用例只记录“本人可见／他人不可见”等判定。
4. 在 PR #6 下集中回复通过及未通过的项、阻塞项和证据。SM-01 对照 NFR-01 全部 50 轮；SM-02 在测试前冻结 E2E-01/02/03/06 的细化场景及分母；SM-03 另行冻结合法预约与正常冲突的自动判定集合及分母。C 分别给出通过数/总数，保留失败、未知和未执行项。

## 可复现的非功能验证

| 项目 | B 使用的条件和判定 | 证据 |
| --- | --- | --- |
| NFR-01 并发唯一性 | 20 个已登录身份携有效 CSRF；每轮预检后由隔离事务临时占位，确认 PostgreSQL 实际观察到 20 个等待写入的连接再回滚占位。50 轮各须 1 次原始 303、19 次目标时段冲突、最终仅 1 条 Confirmed；回收本轮数据，保留 1000 条既有历史。 | nfr-01.json 的 50 组样本，含状态、冲突标记、每次起止时间、实际等待数、终态和清理结果 |
| NFR-02 设备查询 | 100 台设备、1000 条历史、20 个独立账号。预热后每人请求完整 /devices 50 次。每次新建回环 HTTP 连接，计时从发起连接前到读取完整响应，逐行检查编号、名称、位置、状态及本人手机号。1000 条均正确且按升序第 950 个耗时 ≤1000 ms。 | nfr-02.json 保留全部正式样本及 P95 |
| NFR-03 授权与隐私 | 匿名、两个 user、一个 admin；授权验证带有效 CSRF，缺失和无效令牌另测。核对数据库前后状态、所有权和角色边界、完整手机号的展示位置、Cookie、缓存与数据库故障下的输出。 | test_authorization_and_csrf_matrix 及同文件的合法业务路径，配合 test_views 的展示和错误检查 |

单进程 Waitress 24 线程，SQLAlchemy 池 24、溢出 0，PostgreSQL 17.12 最大连接 100。锁观测使用独立连接；测试数据准备、维护和登录预热排除在读延迟之外。设备列表测试使用 Python 标准库 HTTP 客户端和单调高精度时钟。每次完整运行在隔离库执行，不需课程真实账号。

事务证据中的 `clock-*` 记录锁后读取的 PostgreSQL 当前时间、开始边界、原始 HTTP 和独立查询结果。受控边界另测严格小于、等于和大于开始时刻。`commit-rollback-*` 在提交前让数据库返回确定的 SQL 错误；`commit-wire-*` 通过 libpq 发送真实 COMMIT，由另一连接观察提交，可见后关闭尚未读取确认的原连接；`commit-simulated-*` 在正常提交后由测试代码抛异常。后两类分别验证 503 后用 GET 核实。测试控制仅在隔离测试进程中生效。
